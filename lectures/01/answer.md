## 宿題

- 取り組んだレベル：実装
- やったこと：
  - `app/ask.py` に `--chat` オプションと `chat()` 関数を追加し、会話履歴を保ったまま続けて質問できるようにした
  - `client.chats.create(model=MODEL)` で Chat セッションを作り、`send_message()` で質問を送る。Chat は送受信したメッセージを履歴として保持し、毎回履歴ごとモデルに送る
  - 空行・`exit`・Ctrl+D で終了し、終了時に何往復したかを表示する
  - API エラー（429 など）が起きても会話は終了せず、そのまま次の質問を受け付ける
  - 使い方：`uv run python -m app.ask --chat`（従来の1回だけの質問もそのまま使える）
- 結果：
  - 会話モードで「私の名前はタロウです。覚えておいてください。」→「私の名前は何でしたか？」と続けて聞くと、「あなたの名前はタロウさんです！」と答えた（履歴が引き継がれている）
  - 履歴なしの `uv run python -m app.ask "私の名前は何でしたか？"` では「まだあなたの名前を伺っておりません」と答えた
  - `uv run pytest -q` は 11 件すべて成功
- 気づき・疑問：
  - LLM の API 自体は状態を持たない。「覚えている」ように見えるのは、クライアントが過去のやり取りを毎回まとめて送っているからだと分かった
  - そのため、会話が長くなるほど入力トークン数が増え、コストやレート制限（1分あたりのトークン数）にも影響しそう。長い会話では古い履歴を要約したり削ったりする工夫が必要になりそう
  - 3つ目の質問「今の2つの質問をまとめて1文で言ってください」には「あなたの名前はタロウさんでしたね」と答えた。履歴はあっても、指示の意図を正しく汲むとは限らない
